03 · Why Bittensor

Seeded tasks make cheating fail

seed = H(block_hash ‖ miner_hotkey ‖ task_id ‖ counter)

AttackWhy it fails
Pre-record a runThe block hash did not exist yet
Copy another pool’s runTheir hotkey is in the seed
Reuse an old ticketSingle use, expires in about 2 tempos
Forge checkpointsThe validator’s own replay diverges
Fake a success flagSuccess is checked on the replay

Score per run

V = Gate × Demand
× Quality^α
× (1 + β·Novelty)

Gate is pass or fail. Demand is 1× to 5× from paid bounties. Quality covers smoothness, efficiency, idle time and collisions. Novelty is capped.

TALOS

07

The core anti-cheat. Every task is generated from a seed that mixes a recent block hash, the pool’s hotkey, the task and a counter. Any validator recomputes it with no coordination. So you cannot record ahead of time, cannot copy another pool, cannot reuse a ticket, and cannot forge the data because the validator replays it. Each accepted run gets a value: pass or fail gate, times buyer demand, times quality, plus a capped novelty bonus.
