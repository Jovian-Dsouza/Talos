A1 · Miners

How a miner registers and runs

01 · Wallet

Create a coldkey (holds TAO) and a hotkey (the pool’s identity).

02 · Register

Burn TAO with burned_register on the Talos netuid to get a UID.

03 · Publish

ServeAxon writes the pool’s public IP and port on chain.

04 · Serve

Run the FastAPI pool: tickets and uploads for phones, runs for validators.

GET /ticket

phone: seeded task

POST /submit

phone: the recording

GET /status

phone: the verdict

GET /trajectories

validators only, signed

Validator pulls are signed with bt.http_auth and checked against the validator permit on chain, with fresh nonces.

Miners never set weights. Emissions go to the pool’s UID, and the pool pays its people.

TALOS

A1

A miner is a pool. It creates a Bittensor wallet, registers a hotkey on our subnet by burning a little TAO, publishes its HTTPS endpoint on chain with ServeAxon, then runs our FastAPI pool service. Phones talk to the public endpoints; validators pull recordings through a signed endpoint that only accepts hotkeys with a validator permit.
