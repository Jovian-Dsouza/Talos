A2 · Validators

How a validator scores every run

01 · Pull

Signed GET /trajectories from every pool’s on-chain endpoint, every few blocks.

02 · Ticket

Seed derives correctly, block hash is on chain and fresh, ticket used once.

03 · Replay

Native MuJoCo 3.17.0 re-runs the controls. Drift must stay under 0.01 rad and 5 mm.

04 · Success

Checked on the replayed state. The browser’s own flag is never trusted.

05 · Dedup, quality

Near-duplicate paths rejected. Jerk, efficiency, idle time, collisions, gripper chatter.

06 · Weights

Per-pool EMA, then SetWeights each tempo. Merkle root of accepted runs committed on chain.

TALOS

A2

A validator is a staked hotkey with a validator permit running our Python validator. It discovers pools from the metagraph, pulls their recordings over signed HTTP, and runs six steps on each. Weights come from an exponential moving average of each pool’s score and are set once per tempo; Yuma Consensus combines validators. Each epoch the validator also commits one Merkle root of accepted run hashes, so provenance is on chain at a fraction of the cost of per-run records.
